A keyboard-first graph editor

Connect your thoughts, at the speed you have them.

KiDraw turns ideas and their relationships into a picture without making you stop to operate the picture. Create, connect, navigate, and arrange a graph from the keyboard while the interface shows what every key will do.

By Benjamin Berman · GitHub

Why another graph editor?

I wanted the graph to keep up.

Most visual tools make me alternate between two jobs: having the thought, then reaching for the mouse to manufacture the box, drag a connector, and repair the layout. Each step is small. Together they are enough friction to lose the next thought.

KiDraw begins from a different assumption: making the structure should feel more like editing text. The canvas has a crosshair. The keyboard is the primary control surface. The graph responds while your hands remain where the words are coming from.

Stay on the keyboard

Add ideas, connect them, edit their words, move around, and change layout without a trip to the pointer.

The menu is the documentation

The app draws the available keys, then redraws them as the question changes. You can learn by looking instead of memorizing.

Automatic or exact

Let KiDraw arrange the whole graph, or move one item yourself and keep its links legible. The machine helps without taking authorship.

The menu is the documentation

Hold a key and the interface answers.

The keymenu is laid out like the physical keyboard. At rest, only commands that work now are lit. Hold a for Add and the keyboard becomes Add's possible next steps. The canvas answers at the same time with dashed landing places.

The breadcrumb says where you are. The card shapes carry a small grammar of their own: a cut corner means there are more choices; the lift in the opposite corner means the action happens when you release the key.

This is discoverability without a toolbar: the interface can remain dense because it only shows the vocabulary for the current moment.

Manual and automatic

Move one thought. Let its links find their way.

A graph is useful because the links stay distinct enough to read. KiDraw's routing work tries to avoid crossings and, where an intersection cannot be avoided, to avoid the confusing shallow angles that make two links look like one.

Here, I move “Docs” with the keyboard. Its incoming and outgoing links follow it. Then a full-graph layout can restore a regular tree in one command. I am still iterating on the routing design; this sequence shows the intended balance, not a claim that every graph is solved.

Navigation

Move between ideas, not pixels.

Large graphs create a different problem: getting around. KiDraw is experimenting with movement by node and movement by link, so a direction means “take me to the next meaningful thing,” not “move the pointer eight more pixels.”

The model is still a work in progress, and I am judging several versions by feel. One part is already concrete: when the graph is too far out to read, landing on a node raises a full-size reading lens without zooming the rest of the canvas.

A deliberately different starting point

This is not an infinite whiteboard with extra hotkeys.

Obsidian Canvas is a useful reference because it serves many of the same people. Its documented, out-of-the-box flow is visual: double-click or use the toolbar to make a card, drag from a card edge to connect it, and drag cards to arrange them. KiDraw starts with the keyboard and treats arrangement as something the computer can help with.

The comparison is about defaults, not capability. Obsidian has configurable hotkeys, an open canvas format, and a plugin ecosystem. It is also a mature notes application, while KiDraw is an alpha focused tightly on graph interaction.

What I want to learn is whether a keyboard-native editor changes the kinds of graphs people are willing to make—because adding one more relationship becomes cheap enough to do while the thought is still present.

Roadmap

The alpha is a working argument, not a finished product.

The order changes as daily use exposes better questions. This is the current shape of the work, summarized from the task graph I use to build KiDraw.

Now

Make the core feel dependable

Polish the keymenu, refine movement by node and link, improve edge routing, and remove the small inconsistencies that interrupt a keyboard flow.

Next

Give graphs more meaning

Develop diagram types, plugins, tags and style mappings; improve file management; and explore Git and cloud-backed storage without abandoning local files.

Later

Think with other people—and tools

Add human collaboration and AI integration while preserving clear authorship, inspectable files, and the speed of direct manipulation.

The larger experiment

AI makes unusual interfaces cheaper to try.

KiDraw matters to me as a product, but it is also an experiment in how software gets made now. For years, many interface ideas were too expensive to test unless their business case was already obvious. AI-assisted development changes that equation: I can try a held-key menu, use it for real work, throw away the parts that feel wrong, and keep iterating.

There is a recursive part I like: AI agents help build KiDraw from a task graph maintained inside KiDraw. The tool is both the experiment and part of the workshop. That does not make every generated answer good. It makes more questions affordable to ask.

Try it where it is

It is an alpha. Bring a keyboard and expect edges.

KiDraw runs in a desktop browser and works with files on your machine. There is no account and no collaboration yet. Some interactions are still changing quickly, and bugs are part of the current experience. If the premise sounds useful, the live app is the best explanation I have.
