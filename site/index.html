A keyboard-first graph editor

Connect your thoughts, at the speed you have them.

KiDraw draws graphs: boxes for ideas, arrows for how they relate. You build them without leaving the keyboard, and a keyboard drawn on screen shows what each key does at that moment.

This page is one of those graphs. Every picture below is a screenshot of the real app being typed into, one box at a time.

Question one

What is it?

Question oneWhat is it?

What is it?

Three answers, none of them longer than a sentence.

Diagram editor

Boxes, and arrows between them. That is the whole data model: nodes and edges.

Keyboard-oriented

The bindings started from vi, because that is the keyboard language I already think in — and they are meant to be found on screen rather than memorised from a manual.

A WIP experiment

It works, and it is not finished. Whether a keyboard-first diagram editor is actually nicer to use is the open question.

A break from the map

The keyboard on screen is the manual

A four-box graph, so the keyboard is easy to read. At rest it lights only the commands that do something in the current mode. Hold one down and it becomes that command's next choices.

Every frame on this page was taken the same way: a script pressed the keys and screenshotted the result.

Question two

What's the point?

One answer, in three parts.

Question twoWhat's the point?

What's the point?

One answer, in three parts.

Efficiency

Not speed for its own sake. Fewer interruptions between having a thought and having it on screen.

Writing and Connecting

Typing a label and joining it to something else are the same handful of keys, so both land before either slips away.

Navigation

Move between boxes rather than across pixels: skip the empty space, or follow a link to whatever is on the other end.

Learning

The keyboard drawn on screen shows what each key does right now, so the bindings can be explored rather than looked up.

Question three

How does it work?

Five things to know about the keyboard.

Question threeHow does it work?

How does it work?

Five things to know. After those you are guessing correctly.

Press and hold submenu keys

Tapping a key and holding it are two different commands. Holding one opens its submenu, and the keyboard on screen redraws to show what is now available.

Some submenu keys allow you to change how you navigate

Inside a submenu, h j k l can mean something else: stepping between boxes, or between the dashed places a new box could land.

Some submenu keys have an action on release

The lift mark in the corner of a key card means it fires when you let go. That is how holding Add and choosing a direction becomes one gesture.

Press ESC or Ctrl-[ once or twice to get back to the main menu

The same escape hatch as vi. One press leaves the text; a second leaves the box.

Vi-style modal text editing

Inside a box the text behaves like vi — insert and normal, w and b, x and dd.

Move one box; its arrows find new routes

Select+Drag is held while one box steps down. The arrows are not dragged along with it — they are computed again at every step, so the picture stays readable while you are still deciding where the box belongs. Scroll to step through the drag.

Question four

Important features?

What is built today.

Question fourImportant features?

Important features?

The parts that are built, and worth knowing about.

Automatic edge routing

Where an arrow goes is computed rather than drawn, and computed again whenever anything moves. The two breaks after this branch show it working.

Waypoints for fine tuning

When the router picks a route you disagree with, drop a point the line has to pass through. Everything else keeps routing itself.

Node/edge layout on demand

One press re-arranges the whole graph. Every frame on this page had it applied straight after the box was typed.

Coarse and fine movement

Two modifier keys change how far a single press moves the crosshairs.

Navigate by hopping from node to node

Jump to the next box in a direction instead of travelling the distance between them.

Navigate by following edges

Move along an arrow to whatever is on the other end. It is also how the capture script walks back to a parent box.

Zoom, pan, and recenter

Camera commands. Recenter fits the whole graph on screen, which is how the wider frames here were framed.

Node and Edge Styling

Shape, colour, and solid versus dotted versus dashed. Enough to carry meaning, not enough to turn into a design task.

Edge labels

Text attached to an arrow rather than to a box, for when the relationship is the thing that needs naming.

Saving diagrams locally

Files go to your own disk. There is no account and no server.

currently Chrome only

Saving uses the file system access API, which today means Chrome. A download-and-upload fallback would cover the rest; it is not written yet.

A break from the map

Push a box into an arrow, and the arrow goes around it

This is the routing goal that matters most: an arrow should not disappear behind a box. Plan points at Ship it, with Review sitting below them. As Ship it is dragged down, the straight line between Plan and Ship it would run through Review — so the router bends it over the top instead, on every keypress.

Three boxes. Plan points at Ship it; Review sits below, out of the way.1 / 6

The small circle on the line is the point the route is being pulled through. Drop one of those by hand and it becomes a waypoint you control.

Before you open it

It is an alpha. Bring a keyboard.

Chrome, a physical keyboard, and some patience. Saving is local-only and Chrome-only, some arrows still route worse than you would draw them, and the navigation model will change. Anything on this page that is not in a frame is a plan, not a feature.

The 28 boxes above were typed into KiDraw by a script driving the real app — 265 frames of it, captured twice so a phone gets a portrait shape and a desktop a wide one in all, roughly ten per box: the keys held down, the empty box, the label going in a few characters at a time, the layout tween, and the graph at rest. Each frame is held for about as long as the keys it stands for would take to press.
