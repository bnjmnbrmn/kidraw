A keyboard-first graph editor

Connect your thoughts, at the speed you have them.

KiDraw draws graphs: boxes for ideas, arrows for how they relate. You build them without leaving the keyboard, and a keyboard drawn on screen shows what each key does at that moment.

This page is one of those graphs. Every picture below is a screenshot of the real app being typed into, one box at a time.

Question one

What is it?

Five answers, and the detail hanging off them.

What is it?

Five answers. None of them takes longer than a sentence.

Diagram editor

You make boxes and connect them with arrows. That is the whole job.

Technically, a Graph Editor

Diagram is the everyday word; graph is the accurate one.

A "Graph" is basically just a bunch of nodes (boxes, circles, etc) and edges (lines, possibly with arrowheads)

That is the entire data model. Everything KiDraw does is adding, removing, or arranging those two things.

Comparable to

Tools you may already use that draw the same shapes.

Miro

Shared whiteboard, mouse-first.

Microsoft Visio

The corporate standard for diagrams.

Draw.io

Free, browser-based, very widely used.

Excalidraw

Sketchy-looking diagrams, quick to start.

Graphviz (dot)

You write the graph as text and it lays it out. KiDraw borrows that idea of automatic layout, but you build the graph by hand.

Keyboard-first

The mouse is optional. Creating, connecting, moving and arranging are all key presses.

Initial key bindings inspired by the vi coding editor

The first bindings copy vi because that is the layout I already know.

Not just for coders

The bindings come from a code editor. The tool does not assume you use one.

Support other options in the future

Other binding styles are planned. This branch links to that plan further down.

Discover-able shortcuts

A keyboard is drawn on screen showing what each key does right now, so you can find commands instead of memorising them.

An experiment

Whether a keyboard-first diagram editor is actually nicer to use is the open question. I am not claiming it is settled.

Work in progress

The alpha works, and parts of it will change. The list at the end of this page is what is still missing.

A break from the map

The keyboard on screen is the manual

A four-box graph, so the keyboard is easy to read. At rest it lights only the commands that do something in the current mode. Hold one down and it becomes that command's next choices.

Every frame on this page was taken the same way: a script pressed the keys and screenshotted the result.

Question two

What's the point?

Three reasons to build another diagram tool.

What's the point?

Three reasons to build it rather than use one of the tools above.

Graphs are everywhere

Once you notice the shape, it turns up in most of the things you already draw.

Road maps

Places, and the roads between them.

Mind maps

One idea in the middle, related ideas hanging off it.

Logical arguments

Claims, and what supports them.

Outlines are a special type of graph

An outline is a graph where every item has exactly one parent. That covers a lot, but not everything.

The Internet

Pages and links.

Get our thoughts down before they slip away

The point of going fast is not speed for its own sake. It is capturing an idea while you still have it.

Avoid the mouse-keyboard switching bottleneck

Moving a hand to the mouse and back is a small interruption that happens constantly while sketching. This box points back at Keyboard-first, in the branch above.

Make it easier to learn keyboard-based tools

A secondary hope: the on-screen keyboard might make modal editing approachable to people who would not install vim.

Vi and Vim have a learning curve

Mostly because you cannot see what is available. KiDraw shows it.

Question three

How does it work?

The five moves you need on day one. The numbers on those arrows are the order.

How does it work?

The basics first, then everything you can ignore on day one.

Basics

Five steps. The numbers on these arrows are the order to learn them in.

1Move the crosshairs

A crosshair takes the place of the mouse pointer. Moving it is the first thing to learn.

1h for left

Same key vi uses.

2j for down

Down.

3k for up

Up.

4l for right

Right.

using hjkl

Four keys under the right hand, no arrow-key reach.

2Add a node

A box appears under the crosshairs and you are typing into it immediately.

Press and release a

Tap it. Holding the same key does something else, which is where the next step comes from.

3Edit the node's text

Text editing inside a node behaves like vi, including the modes.

Vi style

Insert and normal, w and b, x and dd. Same habits as the editor.

4Exit node edit mode

Leaving the text takes you back to the graph.

Press ESC or Ctrl-[

Both work. The first press leaves insert, the second leaves the node.

5Connect two nodes

Holding Add instead of tapping it turns the same key into connect-and-place.

1Have crosshairs over node

The node you are standing on is where the new arrow starts.

2Press and hold a

The keyboard on screen changes to the choices available while the key is down.

3Use h for left, j for down, k for up, l for right

Dashed outlines show where the new box could land. Pick one and let go.

Question three, continued

The deep end

Movement, styling, routing, layout, saving. None of it is needed to draw your first graph.

Advanced

The rest. None of it is needed to draw your first graph.

Coarse and fine movement

Two modifier keys change how far one press moves the crosshairs.

Navigate by hopping from node to node

Jump to the next box in a direction instead of travelling the distance.

Navigate by following edges

Move along an arrow to whatever is on the other end. This is how the capture run walks back to a parent.

Zoom, Pan, and Recenter

Camera commands. Recenter fits the whole graph, which is how the overview frames on this page were taken.

Node and Edge Styling

Enough styling to carry meaning, deliberately not enough to become a design task.

Shape

Box, circle, diamond, junction, invisible.

Color

A small fixed palette.

Solid vs Dotted vs Dashed

Three line styles, usually enough to separate certain from speculative.

Automatic edge routing

Where an arrow actually goes is computed, not drawn by hand. It runs again whenever anything moves.

Avoid edges crossing under nodes

A line disappearing behind a box is hard to follow.

Minimize edges crossing each other

Fewer crossings, fewer misreadings.

Avoid small-angle crossings

When two lines must cross, a shallow crossing is the one your eye follows into the wrong branch.

Minimize edge length

Shorter lines, all else equal.

"Waypoints" for fine tuning edge routing

When the router picks a route you disagree with, drop a point the line has to pass through. It links back to the routing box above.

Automatic node layout

One command re-arranges the whole graph. Every frame on this page had it applied after the new box was typed.

Save locally

Files go to your own disk. There is no account and no server.

Separate semantic and style files

What the graph means and how it looks are stored apart.

Like HTML and CSS

Restyle without touching the content, or read a diff of the thinking without the colour changes.

Chrome only

Saving uses the file system access API, which today means Chrome.

for now

A download-and-upload fallback would cover other browsers. Not written yet.

A break from the map

Move one box; its arrows find new routes

Select+Drag is held while one box steps down. The arrows are not dragged along with it — they are computed again at every step, so the picture stays readable while you are still deciding where the box belongs. Scroll to step through the drag.

Select+Drag held, before the first step.1 / 11

The last two frames are the release, and then one press of Layout putting the whole graph back into a tidy tree.

A break from the map

Push a box into an arrow, and the arrow goes around it

This is the routing goal that matters most: an arrow should not disappear behind a box. Plan points at Ship it, with Review sitting below them. As Ship it is dragged down, the straight line between Plan and Ship it would run through Review — so the router bends it over the top instead, on every keypress.

Three boxes. Plan points at Ship it; Review sits below, out of the way.1 / 6

The small circle on the line is the point the route is being pulled through. Drop one of those by hand and it becomes a waypoint you control.

Question four

Where is this going?

Planned, not built.

Where is this going?

Planned, not built. Read this branch as a list of intentions.

Other styles of keybindings

vi bindings were the fastest for me to design, not the ones everyone should have to use. This links back to the promise made in the first branch.

1i, j, k, and l

Same shape as hjkl, shifted one key over.

2w, a, s, and d

The arrangement games use.

3arrow keys

The obvious default for anyone who wants one.

4Emacs style

Ctrl and Meta chords instead of modes.

5etc.

Bindings are already data in the code, so adding a profile is not a rewrite.

Collaborate on graphs

More than one editor on the same graph.

with other people

The ordinary version: two people, one diagram.

with AI agents

The version I want: an agent editing the same graph I am editing. Right now the handover between me and the agents on this project happens through files.

Improvements to graph layout/edge routing

Routing is the part I change most often. Some graphs still come out with routes I would not have drawn.

Including alternative algorithms

Different graphs want different layouts, so this should be a choice rather than one built-in answer.

Alternative navigation

Hopping by node and following links are both still being judged by feel. They are the parts I am least sure about.

Temporary views

Change what you are shown without changing what the graph says.

Pull in neighboring nodes

Bring whatever touches the current box next to it, temporarily.

Collapse/expand subgraphs

Fold a branch into one box until you need it again.

Plugins

Things that make sense once the core is stable.

Presentations

Walk an audience through a graph.

Saved series of views

A slide is a camera position, so a deck is a saved list of them.

Diff visualization

What changed between two versions of a graph.

Git integration

Graphs are files, so they can have history like anything else.

Diagram types

A graph that knows what kind of thing it is can be more helpful about it.

1Todo graphs

This project keeps its own task list this way.

2Software architecture

Components and their dependencies.

3Genealogy

Family trees, which are famously not trees.

4etc.

The list is open.

Visual polish

Last on purpose. It is the easiest thing to spend time on and the least likely to change whether the tool is any good.

Before you open it

It is an alpha. Bring a keyboard.

Chrome, a physical keyboard, and some patience. Saving is local-only and Chrome-only, some arrows still route worse than you would draw them, and the navigation model will change. Anything on this page that is not in a frame is a plan, not a feature.

The 96 boxes above were typed into KiDraw by a script driving the real app — 562 frames of it, captured twice so a phone gets a portrait shape and a desktop a wide one in all, five or six per box: the keys held down, the empty box, the label going in, the layout tween, and the graph at rest. Fitted on screen the finished graph sits at 3% zoom, which is the honest reason navigation matters more than a minimap.
