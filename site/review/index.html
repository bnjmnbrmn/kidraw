KiDraw homepage capture review

Raw captures from the running app on a clean synthetic graph: seven nodes, with “Copy” connected to two parents so the graph expresses something an outline cannot. This page preserves the August 31 review set and its known flaws; it is not the homepage itself.

Edges staying legibleDragging a node, links rerouting

Select+Drag is held while “Docs” moves down. Its two links find new routes instead of becoming a fixed bundle.

Layout kickerFull-graph automatic layout

One command returns the graph to a clean three-column tree with no crossings.

NavigationReadable nodes at a distant zoom

At 22% the cards are unreadable specks. Move onto one and a full-size reading lens appears in place, while the rest of the graph remains where it is.

The menu is the documentationAt rest, then with a key held

At rest, only available commands are lit. Hold Add and the same keyboard becomes Add's choices while dashed locations appear on the canvas. The breadcrumb reads add > choose target.

OpeningA graph appearing

Each frame relays the graph as nodes arrive, so arrangement is not a separate task.

Keymenu polishCard labels and the release mark

Long actions now shrink until their widest word fits, so labels wrap between words but never inside one. The bottom-left lift means “fires when you release the key”; the bottom-right chamfer independently means “has more choices.”

Known capture problems

  • The crosshair sits over the “Docs” label in the drag and growth frames.
  • The top row is clipped in the drag frames; that is a capture problem, not an app problem.
  • The drag sequence uses the compact menu while the menu section uses the full keyboard view.
  • By-node and by-link navigation are not captured. Their interaction design is still being judged by feel.
  • “Move by node” and “Move by Link” use inconsistent capitalization.
  • These frames predate the per-axis tree-spacing correction, so their wide nodes sit too close horizontally. The app now derives horizontal-tree corridors from node width.
  • The crosshair overlaps a link in the growth frames and makes an arrow look interrupted.
